# mac2 T7_1T vault operations

This reference supplements the unified `codex-storage-cleanup` skill for mac2-specific T7_1T snapshots, offload, restore, and exact cache or log purges. Follow the parent skill and SOP for discovery, candidate ranking, retention, reporting, and authorization. These operations do not change build locations or schedule themselves. From the child skill directory, use `scripts/vault.py`; inspect its `--help` before an operation. A scan, backup, or skill edit authorizes no local removal.

## Scope and decisions

- Start with the requested account and exact Codex-owned roots. For this Mac, distinguish `/Users/mac2` from `/Users/mac`; do not modify another account merely because it is readable. Use `du`, Git status, project configuration, and process/open-file checks to identify complete generated child directories. Never delete a workspace, worktree, repository, `.codex`, `sessions`, or the live `archived_sessions` directory as a whole; the archive-specific operation may remove only verified JSONL children.
- Keep source, Git metadata, lockfiles, essential configuration, credentials, important documents, unique images, and uncommitted work. Back these up when requested, but do not classify them as regenerable. Generated build/test outputs, installed dependencies, virtual environments, SDK downloads, and caches are candidate artifacts only after their provenance and current use are checked. Check visualization directories item by item: they may contain original media, SQLite state, reports, or final outputs.
- Codex-managed `sessions` and the live `archived_sessions` directory must stay on the same filesystem for normal future archiving. Never symlink only `archived_sessions` to another volume, and never delete the live directory itself. Older archived JSONL files are user data, not cache: they may be offloaded individually after an exact verified snapshot and explicit authorization. Offloaded conversations may disappear from Codex's archived-task list or be unavailable to read until restored; explain this before removal. Do not alter Codex's state DB or pretend that an external snapshot is an automatically readable live archive.
- Before any external write, verify that mounted `/Volumes/T7_1T` is the writable APFS volume with UUID `E70D0032-CFF1-499D-81A2-DA2A661FCAD5` and has enough space. Use `/Volumes/T7_1T/codex/storage-vault/snapshots` for this skill's snapshots. If the disk is absent or unsuitable, stop the dependent operation and ask the user to connect it or choose local execution for that task. Never create a substitute mount directory.

## mac2 cleanup policy

- On an explicit mac2 cleanup run, inspect `/Users/mac2/Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation`. It holds staged app-update packages, not conversation history or source. Use `python3 scripts/vault.py purge-update-cache --confirm-path /Users/mac2/Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation --permanent` to remove that exact cache without backup only when no updater is running and no files there are open. If updating is active or its status is uncertain, defer this step and say why. Do not sweep other `Library` caches or perform this mutation during an audit-only request.
- Inspect `/Users/mac2/Library/Caches/Codex` separately. It is a browser cache, not the Codex support directory or conversation store. On an explicit cleanup run, use `python3 scripts/vault.py purge-browser-cache --confirm-path /Users/mac2/Library/Caches/Codex --permanent` without backup only after the Codex/ChatGPT app has fully quit and no files in that exact cache are open. The command also refuses linked or nested-volume entries. Do not quit the user's app just to make this pass; if it is running, defer and explain that the cache will be regenerated after a later restart.
- Only if the user explicitly requests force-cleaning while the app remains open, use `python3 scripts/vault.py purge-browser-cache-online --confirm-path /Users/mac2/Library/Caches/Codex --force-online --permanent`. It removes only six exact `Cache_Data`/`Code Cache` subdirectories after checking that none are open, linked, or on another volume; it leaves the root, active journal files, and non-cache app data intact. This online operation can make the current browser session reload or recreate cache immediately; report actual space recovered. Do not treat a general cleanup request as authorization for this mode.
- Old diagnostic `.log` files under `/Users/mac2/Library/Logs/com.openai.codex` may be removed without backup on an explicit cleanup run using `python3 scripts/vault.py purge-old-logs --confirm-path /Users/mac2/Library/Logs/com.openai.codex --older-than-days 7 --permanent`. Remove only unopened, regular, user-owned `.log` files whose dated folder and modification time are both older than the retention period; keep recent logs and the directory itself. Say that removed logs will no longer be available for past-incident debugging. This is a small-space cleanup, not a substitute for reviewing large project outputs.
- Inspect old Git-ignored build directories such as `src-tauri/target` per project. For an inactive, verified generated directory, back it up to T7, verify it, then evict its local copy only after authorization covers that exact path and permanent offload method. Preserve the repository, source, Git metadata, and uncommitted changes. If provenance or active use is unclear, report the exact path instead of deleting it. A later build may recreate it locally unless the project's build output is configured separately.
- A prior ChatGPT application backup under a Codex task's `work/backups` may be kept as a verified T7 snapshot and its exact local duplicate removed only with authorization covering that path and permanent offload, provided it is not the installed app or an active backup target. Do not extend this rule to other backups merely by name. Restore from the snapshot on request, without overwriting an existing local destination.
- `visualizations` and task `outputs` can contain original images, music, PDFs, SQLite state, and final deliverables. For each candidate, report its exact task path, size, notable contents, uniqueness/duplicate evidence, live-use status, and what would be inaccessible after offload. Check apparent duplicate output trees by content, not names or sizes alone; identical files at different paths may still be referenced by tasks, and APFS clones may make `du` overstate recoverable space. Wait for the user's approval of those exact paths before moving or removing anything. Never label all visualizations or outputs as regenerable.
- For specifically reviewed W4DJ tests, audio-reader packages, video App outputs, and old app-patch artifacts allowlisted in `scripts/vault.py`, use a `user-data` snapshot and `offload-reviewed-output` only after the user approves those exact paths in the current task. The allowlist is a safeguard, not standing permission. Preserve neighboring directories, the installed applications, and small source or backup-control files; a final package is not exempt when the user explicitly approves its offload.
- For old application-patch work, inspect the children rather than offloading the `work` root: snapshot each approved large extracted or patched artifact, including single files when applicable, and leave small tools, backup records, and the installed application alone. For `.build`, confirm it is generated, inactive, and Git-ignored where a repository exists; keep dirty source and Git metadata untouched.
- The W4DJ `w4dj-300-short-isolated-20260904-v3` directory has absolute symlinks into `w4dj-300-short-isolated-20260904-v2`. If restoring v3, restore v2 to its original path first; a successful v3 content-signature check alone does not make those links usable.
- Keep ordinary `sessions`, live `archived_sessions` directory, generated images, worktree roots, and application state local unless a separate, app-aware decision covers them. Archive offload follows the dedicated workflow below, not the generic build-artifact rule.

## Audit presentation

When the user asks what can be removed, especially for `visualizations`, present a compact table before seeking approval. Group by task/date, show the largest exact child paths rather than one row for the whole root, and include a remainder row if small items matter. Use current measurements, not the sizes from an earlier audit.

| Candidate (exact path) | Local size | Contents and source evidence | Live use / references | Proposed action and restore cost |
| --- | ---: | --- | --- | --- |
| One reviewed task directory | Measured GiB | Original input, generated copy, state, report; source existence versus content-verified duplicate | Open files, running jobs, unarchived or active tasks, absolute-path links | Keep, cache purge, verified T7 snapshot only, or snapshot then offload; say what stops working until restore |

For apparent duplicates, compare file content rather than names, counts, or equal sizes; source files merely existing on T7 is not content verification. Call out cross-directory symlinks and restoration order. Distinguish a directory's `du` total from the actual free-space change measured with `df` after cleanup, because APFS clones, snapshots, and concurrent writes can change the result. Avoid double-counting parent and child directories. If the user names a space target, state whether the estimate reaches the total target or an *additional* target, and separate immediately purgeable cache from outputs needing exact-path approval. A table is a reporting format, never standing authorization to delete its rows.

## Invocation workflow

1. Give a concise, read-only ledger: exact path, type, size, source or rebuild evidence, Git state, active/open status, proposed `delete inactive update cache`, `backup only`, `backup and evict`, or `archive offload`, and restore cost. Do not infer safety from a name or age. Prioritize large verified generated artifacts. Preserve each workspace and worktree root.
2. Apply this policy only within an explicit, scoped cleanup request. A general request to inspect, edit this skill, or back up does not authorize eviction. A permanent purge or offload requires authorization for the exact path or displayed candidate group and method; use Trash or Recycle Bin by default for other eligible items. For newly discovered or ambiguous items, especially visualizations and outputs, show the precise candidate group and seek direction before permanent local removal. Never silently expand to neighboring paths.
3. Run `python3 scripts/vault.py backup --source ABS_PATH --category generated|codex-archives|user-data`. The script records the source path and a content digest, copies to a new snapshot, and compares source with copy. Verify the snapshot again before any eviction.
4. For a verified, inactive, complete generated directory only, run `python3 scripts/vault.py evict SNAPSHOT_ID --confirm-source ABS_PATH --permanent` after the exact action is covered by the cleanup request. This removes the local generated directory, leaving its verified snapshot on T7_1T. It does not create a symlink or change a build tool's configuration. Report that a future build may recreate the local directory unless separately configured.
5. For explicitly authorized archive offload, back up the exact `/Users/mac2/.codex/archived_sessions` directory with `--category codex-archives`, verify the snapshot, confirm it contains only regular `.jsonl` files and no open files, then run `python3 scripts/vault.py evict-archives SNAPSHOT_ID --confirm-source /Users/mac2/.codex/archived_sessions --permanent`. This removes only files included in the unchanged verified snapshot and leaves the local directory ready for future Codex archiving. Never remove newly added or changed files. Record the offloaded file count and snapshot ID; warn that those old tasks may not be available in the app until restored.
6. For ordinary restore, run `python3 scripts/vault.py verify SNAPSHOT_ID`, then `python3 scripts/vault.py restore SNAPSHOT_ID --destination ABS_PATH --confirm-destination ABS_PATH`. Restore refuses to overwrite. To restore archived conversations into the live directory, use `python3 scripts/vault.py restore-archives SNAPSHOT_ID --confirm-destination /Users/mac2/.codex/archived_sessions`; it verifies the snapshot and refuses any filename collision rather than overwriting newer archives. Then inspect the app's archived-task list; do not edit its state DB automatically.
7. For the ChatGPT app backup rule, make and verify a `user-data` snapshot of `/Users/mac2/Documents/Codex/2026-08-31/x20-it-s-a/work/backups/chatgpt-app-20260901-003722`, then use `python3 scripts/vault.py offload-user-backup SNAPSHOT_ID --confirm-source /Users/mac2/Documents/Codex/2026-08-31/x20-it-s-a/work/backups/chatgpt-app-20260901-003722 --permanent`. It refuses a changed or open source. Use the no-overwrite `restore` command to recover it. Cache and old-log deletion need no snapshot, but must pass their checks above.
7a. For an explicitly approved, allowlisted visualization or task output, back up that exact file or directory as `user-data`, verify its snapshot, then run `python3 scripts/vault.py offload-reviewed-output SNAPSHOT_ID --confirm-source ABS_PATH --permanent`. It refuses an altered or open source. Restore via the no-overwrite `restore` command; until restored, any task that reads the old absolute path will not find it.
8. Verify the resulting paths and Git status. Report snapshot ID, external location, counts, bytes, digest result, exact local paths removed or retained, actual `df` space change, and how to restore. For an explicitly authorized online browser-cache purge, also report the cache root's remaining size and that open journals were retained; cache may regrow during app use. Leave unapproved and mixed-content directories untouched.

Recurring runs require a separately configured automation and an explicit cadence. The skill itself does not start one. A scheduled run may audit and create requested snapshots; it must not permanently evict newly discovered paths without scoped authorization.
