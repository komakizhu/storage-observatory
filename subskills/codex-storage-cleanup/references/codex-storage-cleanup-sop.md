# Codex 跨用户跨平台存储清理 SOP

## 0. 目标与总原则

本 SOP 处理 macOS 和 Windows 上 Codex 生成或管理的数据。未指定账号的盘点覆盖所有可读取的本地用户；指定账号或精确路径的请求只处理该范围。mac2 的 T7_1T 快照、转存与恢复另按 [vault 操作说明](t7-vault-operations.md) 执行。核心目标是：

1. 先按请求范围盘点用户和 Codex 相关路径，再分类；未指定范围时盘点所有可读本地用户。
2. 优先识别 Documents/Codex、Documents/ChatGPT 工作区以及 worktree 内占用大的旧构建产物；同组保留最新完整可用的一份。下载缓存默认保留，避免反复下载消耗流量。
3. 仅对有来源证据、确认不在使用、可再生成或已备份的精确路径提出清理候选。
4. 默认优先移入 macOS 废纸篓或 Windows 回收站；永久删除只用于明确获授权的、已验证的可再生成目录。
5. 每个动作都要能说明：属于哪个用户、为什么属于 Codex、为什么现在可以处理、如何恢复、清理后如何验证。

“看起来很旧”“目录名像 cache”“位于 Documents”“磁盘占用很大”都不能单独证明可以删除。目录名、修改时间和大小只能作为候选信号，不能代替来源、使用状态和用户确认。

## 1. 不可违反的边界

- 不把 mac1、其他机器或未知来源的备份混入当前目标。
- 不删除工作区或 worktree 根目录、活动会话、正在运行的任务、未提交的代码、用户文档、项目源代码、配置、锁文件、数据库、认证文件或未知目录。
- 不清空废纸篓/回收站，不删除 APFS、Time Machine 或 Windows 系统恢复点，不修改权限，不为清理而关闭安全软件。
- 不用整个 Documents、Downloads、用户主目录、C:\Users、C:\ 或根目录作为删除目标。
- 不使用宽泛的 rm -rf、Remove-Item -Recurse、通配符或未解析的 $HOME、~、%USERPROFILE% 作为最终删除目标。
- 不因为当前用户具有管理员权限就默认读取或删除其他用户的数据；权限不足时记录并报告，不用提权绕过判断。
- 不把“备份”“归档”“清理报告”解释为删除授权。删除或移入回收站必须在候选清单完成后获得明确授权。

## 2. 用户与平台盘点

### 2.1 先识别平台和可处理的用户

记录当前操作系统、当前账号、可读取的本地交互用户、每个用户的主目录、所有权/权限和是否存在 Codex 数据。

macOS 可检查 /Users 下的用户目录；跳过 Shared、系统保留目录和符号链接，并单独记录无法读取的目录。Windows 可枚举 Win32_UserProfile 中的非特殊本地用户，或检查 C:\Users 下的实际目录；排除 Public、Default、系统服务账户和重解析点。不要把目录名直接当成有效用户身份，必须结合系统用户资料和所有权确认。

每个用户都要建立一条记录：

| 字段 | 要求 |
|---|---|
| 平台/用户 | 真实 OS 和用户标识 |
| 主目录 | 解析后的绝对路径 |
| Codex 根 | 实际存在且确认属于 Codex 的目录 |
| 可读性 | 完整、部分受限或不可读 |
| 活动状态 | 是否有 Codex、agent、构建或编辑器进程使用 |
| 处置范围 | 仅查看、可列候选、已获授权 |

### 2.2 用户级 Codex 路径

不同版本和安装方式可能使用不同位置，以下是探测范围，不是无条件删除白名单：

| 平台 | 优先探测 | 处理要求 |
|---|---|---|
| macOS | 用户主目录/.codex | 逐项识别 archived_sessions、sessions、worktrees、缓存、日志、临时目录和元数据 |
| macOS | 用户主目录/Documents | 只检查有 Codex 来源证据的工作区；不扫描后就删除整个 Documents |
| macOS | 用户主目录/Library/Application Support 下实际存在的 Codex 目录 | 先确认产品归属；数据库、认证和设置默认保留 |
| Windows | 用户主目录\.codex | 逐项识别与 macOS 对应的会话、worktree、缓存、日志和临时数据 |
| Windows | 用户主目录\Documents | 只检查有 Codex 来源证据的工作区；不把其他文档当成 Codex 数据 |
| Windows | 用户主目录\AppData\Local 或 Roaming 下实际存在的 Codex 目录 | 先确认产品归属；设置、凭据、数据库默认保留 |

在执行动作前，把环境变量、快捷方式、符号链接、macOS alias、Windows junction/reparse point 都解析为真实路径；删除校验必须针对真实路径，并拒绝越过用户主目录或已批准的 Codex 根。

## 3. 统一分类模型

将每个发现项归入以下一类，并在报告中保留原始路径：

### A. 受保护的活动/核心数据

包括工作区/worktree 根目录、活动会话、正在写入的日志、当前任务、未提交代码、用户文档、配置、锁文件、数据库、认证文件、项目资源和任何正在被进程打开的文件。默认不删除。

### B. 可再生成且有来源证据的候选

包括确认属于 Codex 或 Codex 任务的缓存、临时目录、旧日志、构建缓存和完整构建目录。只有路径存在、非链接/重解析点、未被使用、可重新生成，并且用户授权后才能处理。

### C. 高风险的用户数据候选

包括归档聊天、已关闭会话、工作区内可能含用户数据的混合旧产物、导出文件、附件和下载内容。先做内容画像与备份/恢复说明，默认移入废纸篓/回收站，不能因年龄或目录名自动删除。

### D. 未知/系统/第三方数据

包括无法确认来源的目录、系统目录、其他应用数据、恢复点和权限受限内容。只报告，不清理。

## 4. Codex 工作区内的旧产物（不删除工作区）

Documents 中的 Codex 工作区、Codex worktree 根目录、源代码和 Git 元数据属于受保护容器。本 skill 只清理容器内部已经确认的旧产物，不删除工作区本身。

“Documents 里是 Codex 建的”仍必须有可验证的来源。优先寻找以下证据：

- Codex 配置、任务元数据、会话记录或工作区清单明确引用该绝对路径。
- 目录包含能指向 Codex 任务或生成流程的项目元数据、日志、manifest 或关联标识。
- 该目录位于用户明确配置的 Codex workspace 根下，且目录内容与任务记录相互对应。

只有名称相似、位于 Documents/Codex、创建时间接近某次任务，不能作为唯一证据。没有强来源证据的父目录归入“未知/需用户确认”，不向下扩大清理范围。

对于每个候选旧产物：

1. 同时记录父工作区和待处理的精确子路径、用户、项目、来源证据、大小、时间和最近使用线索。
2. 检查子路径是否被 Codex、编辑器、终端、构建工具或其他进程使用；父工作区是否为当前任务。
3. 记录父工作区的 git status --short。工作区存在未提交源代码时，不得删除源代码或混合目录；如果子路径已证明是独立、完整、可再生成的产物，脏 Git 状态本身不扩大保护范围，也不能替代子路径证据。
4. 区分构建输出、缓存、临时文件、日志等可再生成内容与用户源文件、文档、资源、下载及配置；无法区分时按高风险数据处理。
5. 即使产物看起来没有用，也要在清单中显示精确子路径，等待用户确认该产物确实不再需要。

用户只授权旧产物时，不得扩大为删除工作区；用户只授权某个工作区内的产物时，也不得处理其他用户、其他项目或父工作区。

### 4.1 清理收益和恢复代价

先查 Documents/Codex、Documents/ChatGPT 中有来源证据的项目，再查 worktree。扫描阶段完成源码入口、workspace 成员、构建命令、Git 忽略规则与编译器/框架产物结构核对：确认是可重建的完整编译输出后，按项目保留最新一份，其余明确建议删除并计入推荐清理量。目录名只确定探测范围，不能单独证明可删。优先处理大产物，不把小缓存放到第一位。

每项说明：建议删的精确路径、保留的最新路径、源码入口与构建命令、源码版本、重建成本与联网可能。用户看到的是“建议删 A，保留 B；A 是编译输出，源码在 C，需要时用 D 重建”。不要求旧新产物功能完全等价或历史日志齐全，也不把分支不同、耗时未知当成保留理由。扫描器尚不支持的构建器由 agent 在同一轮继续读取配置核实；只有源码缺失、混入用户文件或无法确认目录用途等具体问题才能列入未确认项。

生成图片、聊天、附件、独有报告和导出物默认保留。重新调用图片/模型 API 并不能复现同一份产物，且可能消耗费用和流量；它们不能按构建产物套用“只留最新”。

## 5. 会话和归档数据

### 5.1 归档会话

对 archived_sessions 或平台上等价的历史归档目录：

1. 先确认用户、真实路径、所有权、非链接状态和目录归属。
2. 如果用户需要保留历史，先备份到用户指定或明确确认的新目录；不覆盖旧备份。
3. 使用文件数量、总字节数和内容级校验比较源与备份。macOS ExFAT 旁车文件如 ._* 不计入真实聊天数量；Windows 元数据文件也要与真实聊天文件分开记录。
4. 校验失败、出现非预期文件、源正在写入或用户未明确授权时，停止并保留源。
5. 获得授权后只处理已核对的归档文件/目录，不触碰 sessions、配置和整个 Codex 根。
6. 删除后验证备份仍存在、数量/字节数与删除前一致，并报告恢复可能需要应用重建本地索引。

### 5.2 当前或普通会话

sessions、运行时日志和锁定文件默认视为活动数据。不能仅凭文件年龄批量删除。只有在产品格式或明确元数据能证明某个会话已关闭、无写入、无索引依赖，并且用户选择了精确路径时，才可列为高风险候选；默认仍保留。

## 6. 缓存、日志和临时文件

默认保留需要联网重取的内容：Cargo registry（包、索引和源码）、Cargo git 下载缓存、Rust 工具链、npm/pnpm 包仓库、node_modules、Python 虚拟环境、模型下载和 Codex 插件包。它们可以重新下载，但会增加流量、安装和下次编译成本；不计入默认推荐清理量。只有用户另行要求处理这些缓存时才按精确范围评估。

Cargo `target` 是编译产物，不等同于 Cargo registry/git 下载缓存。旧的冗余 target 可按 §7 评估；最新有用 target 及其增量编译状态默认保留，不拆删内部对象文件。

优先产物处理完后，才考虑无活动使用、恢复成本低的旧日志、临时文件和应用缓存。未知缓存不能仅因名字而视为低成本。

可检查 cache、caches、tmp、temp、旧诊断日志、下载中间文件和明确标记为可重建的 Codex 目录，但必须同时满足：

- 路径属于某个已确认的 Codex 安装或 Codex 任务。
- 不是设置、认证、数据库、索引、锁文件、用户附件或唯一输出。
- 没有 Codex、构建或编辑器进程使用。
- 删除后产品可以重新生成，且不会丢失用户意图、项目源文件或聊天历史。
- 路径被列出并获得适当范围的授权。

优先按完整的缓存/临时目录处理，不在内部随意挑删数据库页、对象文件或工具缓存碎片。无法证明可再生的日志和附件归入高风险候选，而不是绿色自动清理项。

## 7. Worktree 与旧构建产物

### 7.1 候选目录

在已确认的 Codex worktree 或 Codex 生成工作区内，检查：

- Rust/Cargo：target、src-tauri/target
- 前端：dist、build、.vite、.next、out
- 工具缓存：项目内明确归属的 .cache、coverage、构建器缓存
- 其他构建目录：只有项目配置或构建日志明确表明它们是可再生成产物时才纳入

不要在整个用户 Documents 或整个磁盘上按目录名批量匹配。target、build、dist 等名称本身不是 Codex 归属证明。

### 7.2 保留与删除判断

按用户和项目分组，每组默认留最新已完成的一份，并额外保留正在使用或用户指定保留的目录。只剩一份就保留。新构建失败/不完整时，保留最近存在可执行文件、库或框架完成标记的一份。使用这些实际输出的时间选最新，不用父目录 mtime。不同分支、提交、debug/release 和架构不自动拆成保留组；源码还在，旧配置需要时可以重建。

扫描器核对源码、构建配置和生成目录结构，给出恢复命令；这是可重建性静态核查，不是假称重新编译已经通过。不额外编译或下载做盘点。重建耗时未测量就明确写出；保留依赖缓存，缺少依赖可能需要联网时如实说明，不因为耗时未知就排除可重建大产物。

普通 `target`、`build` 可能同时包含多种配置或架构。选中为最新保留目录时整个保留；属于其余可重建目录时整个建议删除。识别自定义 `target-*` 和配置指定的输出根，禁止把内部 `debug/build` 当作独立候选或重复统计。不得手拆 incremental、对象文件或内部缓存。

用 Git common-dir 或同源仓库地址识别同项目的 worktree/副本；不同用户分开。同名但不同仓库不能合并。活动产物暂留，Git 脏状态只保护改动的源文件和混合目录，不禁止清理独立的生成目录。

只有同时满足以下条件的完整目录才可进入删除清单：

- 路径位于已批准的 Codex 工作区内，解析后不是链接或重解析点。
- 该产物目录没有被运行程序或构建进程使用；项目仍在开发不意味着所有历史构建目录都必须保留。
- 目录是完整的可再生成产物，不是源代码、资源、配置或用户输出。
- 同一用户/项目保留最新已完成的产物目录，记录精确路径和实际输出证据；或用户明确授权不保留该项目的产物。
- 删除整个已确认目录，不手工挑删单个 .o、.rlib、incremental 或其他内部文件。

旧 worktree 根本身含有代码和 Git 元数据，始终不是本 skill 的删除对象。只对其内部已确认的完整构建目录、缓存或临时目录列候选；工作区是否有未提交内容用于保护源代码和混合目录，不得被解释为允许删除 worktree 根。

## 8. 清理前候选清单与授权

默认在 Codex 对话中直接给出概览，不要求用户打开 HTML：缓存/临时文件一类（通常保留），构建产物给出“每项目保留最新一份”和“一份也不留”两个互斥方案，各显示 GB 数和差额。会话记录、生成图片另外显示占用，默认保留，不归为可删缓存。HTML 与精确路径台账仅作为补充。

“一份也不留”仅针对已核实可重建的构建产物，包含默认保留的最新目录；源码、依赖和 Cargo 下载缓存不在此范围。计算方式为：全删构建估算 = 已核实构建目录总量 - 已知正在使用部分；使用状态未检查的部分单独注明。两个方案不能相加；估算第二方案不能扩大默认删除白名单。询问“全删能清多少”只要求估算，不是执行授权。

执行任何移动或删除前，先展示候选清单：

| 建议与优先级 | 用户/平台 | 拟删精确路径与大小 | 保留最新路径/替代证据 | Codex 来源与源码/重建命令 | 联网/重建成本 | 活动/Git 状态 | 风险/恢复 |
|---|---|---|---|---|---|---|---|

先给结论：“建议删除可重建旧产物 X，保留最新构建 Y 和下载缓存 Z”。扫描完成时必须已对支持的构建类型作出删除/保留决定，不能把整批大目录都留在草稿中。推荐旧产物量、次选量、具体未确认项和保留量分别统计。移入同盘回收站通常不立即释放磁盘空间，区分目录移走量与实际可用空间变化。

候选清单必须区分：

- 只读检查项；
- 可移入废纸篓/回收站的项；
- 可永久删除的、明确可再生成的项；
- 因权限、来源或活动状态而跳过的项。

“清理所有没用的 Codex 文件”需要先落成清单；对其他用户、Documents/worktree 内的候选产物、归档聊天和备份，必须让用户确认清单范围。授权至少应覆盖用户/平台、精确产物路径或候选组、移入回收站还是永久删除、是否允许处理备份。未覆盖的父工作区和其他路径不得顺手处理。

## 9. 平台动作与路径保护

macOS 默认使用废纸篓流程；Windows 默认使用回收站流程。移动前再次检查真实路径、所属用户、链接属性、活动进程和授权清单。永久删除只适用于已授权、已校验的可再生成目录；用户数据默认不永久删除。

路径保护必须同时限制：

- 目标位于当前授权的用户 Codex 根内，或位于已确认的 Codex workspace/worktree 内部；目标不能等于这些根目录；
- 目标匹配允许的完整目录类型；
- 目标不是源代码、配置、数据库、认证、活动会话或用户文档；
- 目标不是符号链接、junction、alias 或 reparse point；
- 解析后的路径没有越界。

任何检查失败都要停止该项并保留其他数据，不扩大删除范围。不要清空废纸篓/回收站来“确认释放空间”。

## 10. 操作后核验与恢复

每个用户、每个平台和每类动作分别核验：

- 目标是否已移入正确的废纸篓/回收站或按授权永久删除；
- 未授权路径仍存在；
- 工作区/worktree 根、sessions、活动任务、源代码、Git 状态、配置和备份未被改变；
- 实际释放空间与估算差异；
- 没有活动进程继续持有已删除文件；
- 归档备份仍可读取，恢复路径和限制已记录。

空间没有立即释放时，只检查打开的已删除文件、平台文件系统回收机制和系统快照；不自动删除快照或停止备份系统。恢复时保留原备份，先停止相关写入，再恢复精确文件，并说明应用索引可能需要重建。

## 11. 完成报告

报告必须包含：

- 平台与用户范围；哪些用户成功检查、哪些因权限或不存在而跳过；
- Codex 根和 Documents/workspace 探测范围；
- 候选总数、按类型和风险分类的大小；
- 每个实际处理的精确路径、动作、用户、释放空间和恢复方式；
- 归档备份路径、真实文件数量、总字节数、校验结果和旁车文件说明；
- 明确声明未触碰的工作区/worktree 根、活动会话、未授权用户数据、源代码、配置、认证、Git 状态、废纸篓/回收站内容和系统快照；
- 如果空间未立即释放，说明打开句柄或平台回收机制；
- 未处理项及其具体原因。

## 12. 报告视觉方案

本 skill 不另造视觉语言。生成清理报告或 dashboard 时，读取并复用主 skill [存储观察站](../../../SKILL.md) 的“数据口径”“可视化交付契约”“当前色系与语义”“默认浏览器预览与本地操作”规则：沿用 Lieflat Charts Wire 的黑灰底、梅子绿/橙色变化语义、2×2 图表结构、F11/F2/G10 视图、结论优先的报告顺序、一次性视口懒加载和本地服务路径白名单。

清理专属内容只新增数据维度：用户、平台、产物类型、来源证据、风险、可恢复性、精确子路径和实际释放空间。清理候选比例条按各类别内部最大产物缩放，使用中性灰，不用新的颜色；工作区根目录和源代码只作为受保护上下文展示，不能渲染为可删除卡片。
